# `.mcp.json` notes

Sibling file because JSON has no comments — anything explanatory lives here.

## What this file does

Claude Code auto-registers every server listed in a plugin's `.mcp.json` when
the plugin is installed. Our server is `total-recall`, a stdio FastMCP server
exposing read-only recall tools (`recall`, `prior_sessions_for_cwd`,
`find_failed_attempts`, `find_user_preferences`, `get_session_digest`,
`search_messages`) backed by the local SQLite index produced by the
`total-recall index` CLI.

## Variables

- `${CLAUDE_PLUGIN_ROOT}` — absolute path to the installed plugin root (Claude
  Code substitutes this at spawn time).
- `${CLAUDE_PLUGIN_DATA}` — per-plugin data dir (typically
  `~/.claude/plugins/data/total-recall/`). We point the server at it via
  `TOTAL_RECALL_DB_DIR` so the index DB lives in a stable, predictable
  place.

## Transport

stdio only.

- SSE has been deprecated upstream.
- HTTP is unnecessary because Claude Code spawns the MCP server as a child
  process per-session.
- Plugin-bundled MCPs are **not** auto-reconnected — Claude Code respawns
  them per session, so a clean stdout/stdin loop is all we need.

## Why `uv run`

`uv run --directory <root> python -m mcp_server` is zero-install for users
who already have `uv` (which Claude Code itself uses internally). It pins
to the plugin's pinned Python and locked deps without polluting any user
venv.

## Fallback for users without `uv`

If a user doesn't have `uv` on `PATH`, swap the `.mcp.json` entry to use the
system / venv Python instead. They must first install the package so
`python -m mcp_server` resolves:

```bash
cd "${CLAUDE_PLUGIN_ROOT}"
pip install -e .
```

Then edit `.mcp.json`:

```json
{
  "mcpServers": {
    "total-recall": {
      "command": "python",
      "args": ["-m", "mcp_server"],
      "env": { "TOTAL_RECALL_DB_DIR": "${CLAUDE_PLUGIN_DATA}/total-recall" }
    }
  }
}
```

(Any Python on `PATH` that resolves `mcp_server` will work — e.g.
`/usr/bin/python3`, a project venv's `python`, etc.)

## Sandboxing reminders

- The server reads `~/.claude/projects/` **only** via the SQLite index (the
  content is already secret-scrubbed during ingest by the extractors layer).
- It never writes to `~/.claude/projects/`.
- The DB lives under `${CLAUDE_PLUGIN_DATA}` with `0700` perms (server creates
  the dir if missing).
